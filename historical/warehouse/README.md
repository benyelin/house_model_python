# Election Data Warehouse

## Purpose

This warehouse provides a reproducible, shared historical data layer for the
House and Senate forecasting models.

It stores factual historical information separately from model-derived fields.
Production models and historical backtests consume processed warehouse tables
rather than editing raw historical data directly.

## Core principles

1. Raw source files are immutable.
2. Every dataset has source attribution and retrieval metadata.
3. Processed tables are generated by scripts and are not manually edited.
4. Model-specific outputs do not belong in the raw warehouse.
5. House and Senate use parallel schemas wherever possible.
6. Historical snapshots contain only information available as of the snapshot
   date.
7. Ambiguous identities and race structures are resolved through explicit,
   version-controlled override tables.
8. Validation must occur before processed data is used by a model.

## Directory structure

### raw/

Original or minimally transformed source files:

- elections/
- candidates/
- officeholders/
- presidential_results/
- polling/
- national_environment/

### processed/

Canonical normalized datasets:

- elections/
- candidates/
- races/
- snapshots/

### schema/

Machine-readable definitions of canonical fields and validation rules.

### reference/

Stable cross-cycle reference tables such as state codes, regions, candidate
aliases, district identifiers, and election dates.

### overrides/

Explicit manual corrections and identity mappings.

### manifests/

Source and build manifests for each dataset and cycle.

### validation/

Generated validation reports and anomaly audits.

## Initial implementation order

1. Migrate the completed 2022 House election results.
2. Migrate the 2022 House candidate registry.
3. Produce a canonical 2022 House race table.
4. Add 2020 presidential results using 2022 congressional boundaries.
5. Add national environment inputs.
6. Run the first 435-district House backtest.
7. Reuse the same structure for the 2022 Senate cycle.
8. Expand to 2018, 2020, and 2024.

## Relationship to existing historical folders

The existing `historical/house/` files remain in place while the warehouse is
introduced. Nothing should be deleted or moved until warehouse outputs have
been validated against the existing files.
