# House Historical Backtesting Framework

## Purpose

This directory stores reproducible historical House election data used to
evaluate and calibrate the production forecasting model.

Historical source files should contain factual information only. Model-derived
fields are rebuilt by scripts so that historical backtests always use the
current production methodology.

## Directory structure

- `raw/<cycle>/`
  - Immutable or minimally transformed source data
  - Official election results
  - Candidate and incumbency data
  - Presidential district baselines
  - Historical polling
  - National environment snapshots

- `processed/`
  - Normalized and validated historical datasets
  - Generated by ingestion and build scripts
  - Should not be edited manually

- `schema/`
  - House-specific extensions to the shared schema

- `../shared/schema/`
  - Canonical fields shared across House and Senate

## Initial cycle order

1. 2022
2. 2018
3. 2020
4. 2024

## Core rules

1. Raw source files should not contain model outputs.
2. Every source row should include source attribution and retrieval date.
3. Derived fields should be rebuilt rather than manually entered.
4. Every cycle should validate expected race counts and unique race IDs.
5. Uncontested and unusual races remain in the database but may be excluded
   from selected scoring metrics with an explicit documented rule.
6. Historical snapshots must use information that would have been available
   on the represented date.
7. Production parameters must not be calibrated and evaluated on the same
   held-out cycle without clear labeling.

- Incumbency and open-seat status

- National environment snapshot
